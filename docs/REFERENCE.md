## 1. Слова

Где понятие есть в GLPI, плагин берёт слово GLPI.

| На экране | Что это |
|---|---|
| маршрут, меню «Маршруты этапов», вкладка заявки «Маршрут этапов» | порядок этапов для заявок |
| этап; «Как выполняется»: «Задача», «Дочерняя заявка», «Согласование» | одна часть работы |
| инициатор заявки | в GLPI — «Инициатор запроса» |
| исполнитель; «Группа», «Группа отдела» | кто делает работу; в GLPI — «Группа специалистов» |
| согласующий | кто отвечает на запрос на согласование |
| администратор маршрутов | у кого «Маршруты этапов»: «Чтение» и «Обновление» |
| дочерняя / основная заявка | заявка группе отдела / заявка, по которой идёт маршрут |
| этап согласования | этап согласования GLPI — всегда полностью |
| «Не нужен по условию» / «Пропущен» | условие не выполнено / пропущен вручную |
| попытка | ещё один проход по этапам в той же заявке |
| «Назначение формы» | в GLPI — «Место назначения формы» |

## 2. Как выполняется этап

| «Как выполняется» | Что создаётся | Чем заканчивается |
|---|---|---|
| «Задача» | задача в этой заявке; группа на время этапа — исполнитель заявки | «Завершить этап» и «Что сделано» |
| «Дочерняя заявка» | заявка группе отдела «‹этап› — к заявке №N»; в строке этапа — ссылка «№…» | «Результат отдела» → «Отметить результат»; дочерняя решается сама |
| «Согласование» | запрос на согласование GLPI в этой заявке | «Одобрить» или «Отказать»; результат — «Согласовано» или «Отклонено» |

- Номера идут через 10. Номер меняют в «Дополнительно» → «Порядок» или
  стрелками ↑ ↓ в списке этапов.
- У дочерней заявки: «Где создать дочернюю заявку» — в организации основной
  заявки, группы или указанной; группа отдела должна быть там видна. «Как
  отдел сообщает результат» — «Исполнитель отмечает результат» или
  «Согласованием в дочерней заявке».
- Согласование и дочернюю заявку без ответа закрывает только «Закрыть
  принудительно…» с причиной; результат такого этапа — «Выполнено».

## 3. Кто согласует

Поле «Кто согласует»:

- **«Задан в этапе»** — «Согласующие — пользователи» или «Или согласующие
  группы», не больше 50 запросов. «Любой из группы» — один запрос группе,
  «Каждый в группе» — каждому участнику.
- **«Указывает исполнитель заявки»** — он нажмёт «Указать согласующего»
  и напишет причину.
- **«Согласование из формы»** — запрос отправляет форма GLPI. Нужны форма
  и назначение маршрута, а в назначении — этап согласования; его же выберите
  в «Этап согласования в форме». Условия у такого этапа нет.

«Нужно одобрений, %» (в «Дополнительно»): 100 — все, 50 — половина; считается
как в GLPI. Перед отправкой маршрут проверяет каждого согласующего
([RIGHTS.md](RIGHTS.md#право-glpi-на-согласование)).

Согласование из формы засчитывается само, только если все запросы этапа
согласования создала форма. Иначе исполнитель заявки нажимает «Засчитать
согласование» с причиной; уже отвеченное засчитывает администратор маршрутов.

## 4. Условия и вопросы этапа

**«Когда выполнять»:** «Всегда» или «Только если выполнены условия» — иначе
этап «Не нужен по условию»: ничего не создаётся, маршрут идёт дальше.

- «+ Добавить условие» — до трёх; «Нужны»: «все условия» или «хотя бы одно».
- «Что проверяем»: «Вопросы этапов выше», «Ответы формы · ‹раздел›», «Этап
  не нужен по условию», «Категория заявки».
- Под условием — фраза: «Этап выполняется, если на этапе 20 ответили «да»
  на «Нужна закупка?».»
- Условие проверяется, когда маршрут доходит до этапа, и ссылается только
  на этапы выше.

| Что проверяем | Сравнения |
|---|---|
| список, радио, флажки | любой из; ни один из; неизвестно |
| пользователь, группа, категория | любой из; заполнено; не заполнено; неизвестно |
| текст, файл | заполнено (приложен); не заполнено; неизвестно |
| дата | раньше / позже, чем через N дней после подачи; заполнено; не заполнено; неизвестно |
| число | равно; не равно; меньше; не больше; больше; не меньше |
| вопрос этапа выше | да; нет; неизвестно |
| этап выше | не нужен по условию; выполнялся |

**«Если ответа нет»** — ответа нет, если заявка не из формы или вопрос скрыт.
Неизвестный ответ — не «нет». Варианты: «выполнять этап» или «спросить
исполнителя заявки» («Выполнять этап?» → «Выполнить этап» / «Этап не нужен»
с причиной; у согласования решает администратор маршрутов).

**«Вопросы этапа»** — до четырёх «да / нет». Отвечает исполнитель
в «Завершить этап» или «Отметить результат», согласующий — «Вопросы этапа»
в своей строке → «Сохранить ответы» или «Сохранить и одобрить», и в
самообслуживании тоже. Отвечает только тот, кому адресован запрос этапа
(или его заместитель). Одобрил без ответов — этап ждёт ответов, согласующий
отвечает потом там же. На ответы опираются условия этапов ниже.

## 5. Запуск маршрута

- **По ответу формы** (только заявки) — блок «Запуск маршрута»: «Форма»
  (сохранить), «Назначение формы», «Запускать, если»: «Не запускать
  по форме», «Всегда» или «Только если выполнены условия».
- **Бизнес-правилом** — **Администрирование → Правила → Бизнес-правила для
  заявок**, действие «Запустить маршрут этапов». Правило видит маршруты своей
  организации и вышестоящих с «Подчинённые организации» — «Да».
- **Вручную** — вкладка «Маршрут этапов» → «Запустить маршрут» (администратор
  маршрутов).

**Выбор по форме.** Для каждой заявки формы берутся включённые маршруты с этой
формой и назначением, подходящие по организации. Подошёл ровно один —
запускается. Два, ни одного или ответ неизвестен — маршрут не запускается,
отправка не блокируется, заявка остаётся в группе назначения; строка
готовности покажет такие заявки за 30 дней.

**Один путь на форму.** Если у формы есть маршрут с «Запускать, если»,
правило маршрут для её заявок не запускает — готовность маршрута, который
запускают правила, называет такие формы. Условия маршрутов одной формы
должны исключать друг друга — готовность покажет пересечения и пробелы,
а блок — «Другие маршруты этой формы».

**С правила на форму:** выберите форму, назначение и «Запускать, если»;
проверьте готовность; отправьте пробную заявку; выключите правило.

## 6. Результат, отказ, уточнение

**Отказ** — «Что делать при отказе»:

- «Отказать инициатору и закончить маршрут» — заявка решается «Отказ на этапе
  «…».» с причиной;
- «Остановить маршрут» — дальше решает администратор маршрутов.

Неотвеченные запросы этапа при отказе, возврате, отзыве и прерывании
снимаются; данные ответы остаются.

**Вернуть на уточнение.** «Куда вернуть после уточнения» — с каких этапов
можно продолжить; пусто — вернуть нельзя: пока ничего не отмечено, под полем
«Ничего не отмечено — вернуть на уточнение нельзя.».

1. Исполнитель дочерней заявки или согласующий пишет, что уточнить, и выбирает
   «С этапа», если вариантов несколько.
2. «Ждём ответа инициатора» (сам инициатор видит «Ждём вашего ответа»):
   инициатор отвечает публичным комментарием в заявке.
3. Вернул этап согласования — маршрут продолжается сам, в том числе от
   письма через сборщик почты: этап открывается заново, те же согласующие
   (и согласующий из формы) получают новый запрос — все, кого спрашивали,
   и уже одобрившие тоже; «Нужно одобрений» — прежнее. Повторный комментарий
   ничего не меняет. Если ответ сразу не учтён (одновременные действия,
   сбой), маршрут продолжит «Сроки этапов».
4. Вернул исполнитель, согласующий больше не подходит заявке или ответ пришёл
   не комментарием — исполнитель основной заявки или администратор маршрутов
   нажимает «Продолжить». Этап выбирать не нужно: он выбран при возврате.

Дальше — новая попытка; прежние результаты в «Истории этапа».

**Меню администратора маршрутов:**

- «Начать заново с этапа…» (меню строки) — после отказа, прерывания или конца
  маршрута; решённую заявку сначала откройте в GLPI.
- «Возобновить маршрут» (меню шапки) — только после сбоя: группа не видна,
  срок не помещается. После отказа его нет — «Начать заново с этапа…» или
  «Прервать маршрут…».
- «Прервать маршрут…» — с причиной для инициатора; заявку потом решают
  обычным способом.

**Конец маршрута:** заявка решается сама — «Заявка выполнена: все этапы
маршрута «…» пройдены. Результат: …». Инициатор принимает решение, как обычно.
«Отозвать заявку» (если разрешено) прерывает маршрут и решает заявку
с причиной.

## 7. Сроки и статус заявки

- «Срок этапа» — в рабочих днях или часах по календарю маршрута; пусто —
  без срока. Просрочку раз в 15 минут отмечает «Сроки этапов»
  (`itilflow_deadlines`): пометка, комментарий, запись в журнал.
- Это же действие догоняет этап согласования, если ответ согласующего
  сохранён, а этап не сдвинулся (например, при одновременных ответах), —
  если ответ дал тот, кому запрос адресован сейчас (или его заместитель),
  — и продолжает маршрут от ответа инициатора, который маршрут сразу
  не учёл. Сверяются все идущие этапы. Нужен работающий cron GLPI.
- Сроки и SLA позже 18.01.2038 не сохраняются.
- «Статус заявки на этапе» (в «Дополнительно») ставит `itilflow_status_sync`
  в течение минуты; «Не менять» — не трогать.

## 8. Готовность и схема

**Строка готовности** над формой маршрута и списком этапов: «Готов к запуску ·
4 этапа · запускается по ответу формы «…»» или «Не готов к запуску: N проблем»
со ссылкой на этап. У того, кто может изменять маршрут, пересчитывается без
сохранения, как и «Что дальше» на форме этапа.

**«Схема»** — вкладка маршрута: этапы сверху вниз, возвраты слева, обходы
справа. На заявке — маршрут таким, каким он был при запуске.

**Версия** растёт при каждом сохранении; начатые заявки идут по своей версии.

## 9. Действия не по порядку

«Если действие не по порядку этапов» (в «Дополнительно» маршрута):
«Только записать» → запись в «Журнал маршрута»; «Предупредить» — ещё
и предупреждение; «Запретить» — действие отменяется. Права на заявку
проверяются всегда.

Начните с «Только записать», через месяц разберите журнал, затем
«Предупредить» и «Запретить».

**«Решить заявку — только после всех этапов»** (там же) — «Да»: пока маршрут
идёт или остановлен, заявку нельзя решить или закрыть — ни решением, ни
статусом — при любом «Если действие не по порядку этапов». Решить раньше
может только тот, у кого право «Закрытие этапа без ответа»; это пишется
в «Журнал маршрута». «Нет» — маршрут решение не держит. Заявки, запущенные
до 1.13.3, решаются по прежнему правилу: решение отменялось только при
«Запретить», а при «Предупредить» и «Только записать» сохранялось
с записью в журнал. Маршрут прежнего порядка — тоже по прежнему правилу.

## 10. Кто что видит

| Кто | Что видит на вкладке «Маршрут этапов» |
|---|---|
| исполнители и согласующие (центральный интерфейс) | все этапы, «если …», причины «Не нужен по условию», вопросы этапа, «Лист согласования» |
| инициатор заявки | таблицу без условий и вопросов этапа — если включено «Вкладка маршрута у инициатора»; «Отозвать заявку» |
| согласующий в самообслуживании | «Одобрить или отказать» в своей строке; если у этапа есть вопросы — «Вопросы этапа» с «Сохранить и одобрить». Пока его ждут вопросы этапа, вкладку он видит и без «Вкладка маршрута у инициатора» |
| администратор маршрутов | ещё «Схему», «Журнал маршрута», меню «…» |

Кнопку действия видит только тот, кто может его выполнить. На телефоне строки
— карточки. Дочерняя заявка показывает свой этап на вкладке «Результат отдела».

**«Лист согласования»** — печатная сводка по этапам, с комментарием
согласующего. **«Узкие места
маршрутов»** — ссылка над списком маршрутов: длительность этапов, просрочки,
отказы; узкое место — где максимум намного больше медианы.
