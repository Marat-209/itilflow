# Установка и обновление

**[English](INSTALL.en.md)** · Русский

## Требования

| Что | Требование |
|---|---|
| GLPI | 11.0.x (объявлено 11.0.0–11.99.99). Проверено на 11.0.8 |
| База | MariaDB или MySQL 8, таблицы InnoDB; соединение GLPI — с настройкой по умолчанию `autocommit=1` |
| PHP | версия, которую требует ваша GLPI |
| Cron | системный запуск `front/cron.php` раз в минуту |
| Прочее | ничего: без composer, npm и внешних сервисов |

Сроки этапов хранятся до 19.01.2038 — так хранят даты и сама GLPI, и база.

## Установка

### 1. Файлы

Каталог плагина должен называться `itilflow` и лежать в `plugins/` вашей GLPI.

```bash
tar -xzf itilflow-1.13.1.tar.gz -C /var/www/glpi/plugins/
chown -R www-data:www-data /var/www/glpi/plugins/itilflow
```

Или скачайте архив `itilflow-1.13.1.zip` со страницы выпусков (Releases) этого
репозитория и распакуйте его в `plugins/` — внутри уже лежит каталог `itilflow`:

```bash
unzip itilflow-1.13.1.zip -d /var/www/glpi/plugins/
chown -R www-data:www-data /var/www/glpi/plugins/itilflow
```

Путь и веб-пользователя подставьте свои. Архив собирайте на Linux
(`git archive --prefix=itilflow/ -o itilflow-1.13.1.tar.gz v1.13.1`): у архива,
собранного на Windows, у каталогов может не оказаться права `x`, и GLPI отдаст
404 на файлы плагина.

### 2. Установка и включение

Из каталога GLPI, от веб-пользователя:

```bash
php bin/console plugin:install itilflow --username=<администратор GLPI>
php bin/console plugin:activate itilflow
php bin/console cache:clear
```

Или **Настройки → Плагины** → «Установить», затем «Включить» — и всё равно
`cache:clear`: без него GLPI может показывать старые экраны. Если в PHP
выключена проверка изменений файлов (`opcache.validate_timestamps=0`),
сбросьте и OPcache или перезапустите веб-сервер.

Установка создаёт таблицы, проверяет их и при расхождении останавливается
с сообщением — тогда не продолжайте, а разберитесь.

### 3. Автоматические действия

**Настройки → Автоматические действия:**

| Действие | Что делает | После установки |
|---|---|---|
| `itilflow_status_sync` | раз в минуту ставит заявке статус этапа | **выключено** — включите: статус «Запланировано», режим CLI |
| `itilflow_deadlines` («Сроки этапов») | раз в 15 минут отмечает просроченные этапы и догоняет этапы, где ответ согласующего сохранён, а этап не сдвинулся | включено |

Оба работают только от системного cron:

```cron
* * * * * www-data php /var/www/glpi/front/cron.php
```

Пока `itilflow_status_sync` выключено, над списком маршрутов висит
предупреждение, а статус заявки по этапам не меняется.

### 4. Права

**Администрирование → Профили → ‹профиль› → вкладка «Маршруты этапов».**
Кому что выдать — [RIGHTS.md](RIGHTS.md).

### 5. Проверка

- `php bin/console plugin:list` — itilflow 1.13.1 «Включен».
- В меню **Администрирование** есть **«Маршруты этапов»**.
- В `files/_log/php-errors.log` нет ошибок со словом `itilflow`.

## Обновление с 1.10 и новее

Одной установкой, промежуточные версии не нужны. Маршруты, этапы и идущие
запуски не переписываются.

1. **Резерв:** таблицы `glpi_plugin_itilflow_*`, каталог `plugins/itilflow`
   и, как всегда, вся база.
2. **Файлы:** замените содержимое `plugins/itilflow` новыми файлами, старые
   удалите.
3. **Установка:** `plugin:install`, `plugin:activate`, `cache:clear`, как выше.
   Пока `plugin:install` не выполнен, GLPI держит плагин выключенным
   («Для обновления»), и маршрутов на заявках не видно.
4. **Права:** проверьте вкладку «Маршруты этапов» у нужных профилей.

После обновления:

- идущие заявки продолжают путь с того же этапа, по настройкам на момент
  запуска;
- с 1.12 и раньше у всех маршрутов «Запускать, если» — «Не запускать
  по форме»: их запускают те же бизнес-правила. На запуск по форме маршрут
  переводится вручную ([REFERENCE.md](REFERENCE.md#5-запуск-маршрута));
- с 1.13.0 на 1.13.1 структура базы не меняется;
- этапы, сохранённые до 1.13, не пересматриваются: если у вас есть сроки или
  SLA на годы вперёд, откройте такие этапы и сохраните — срок проверится.

## Обновление со старых версий

С 1.7–1.9 — тот же порядок: миграция накопительная. Маршруты, заведённые
давно, работают по прежнему порядку; на новый их переводит кнопка «Перевести
на новый порядок» на странице маршрута. Сначала обновите копию рабочей базы.

## Откат

- **На 1.12 и новее** — верните файлы прежней версии и выполните
  `plugin:install`, `plugin:activate`, `cache:clear`. Новые поля остаются
  в таблицах и прежней версии не мешают.
- Если маршруты переведены на запуск по форме, а откатываетесь на 1.12, снова
  включите их бизнес-правила: 1.12 по «Запускать, если» не запускает.
- **На более старые** — только восстановлением резерва таблиц и каталога.
  Всё, что маршруты сделали после резерва, теряется.

## Удаление

**Настройки → Плагины** → «Отключить», затем «Удалить» (или
`plugin:deactivate` и `plugin:uninstall`). Права плагина снимаются. Таблицы
маршрутов и этапов переименовываются в `*_backup_<дата>`, таблицы запусков
остаются: история заявок не теряется.
